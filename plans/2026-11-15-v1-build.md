# Seasign v1 build plan

## Context

Seasign is an iPhone app that puts the user's day on one screen with no ads and no hidden algorithm. The repository holds only agent scaffolding; `api/`, `openapi/` and `ios/` do not exist and the task board is empty. This session settled the open product questions and changed the calendar approach. This plan records those decisions in the docs, then builds v1 as a sequence of board tasks. Everything in v1 runs locally (Simulator + `wrangler dev`); nothing is deployed and no cloud resource is created.

## Decisions from this session

| topic | decision |
|---|---|
| App identity | One root file holds the bundle ID and team ID, filled with test values until the Apple Developer account is approved |
| Signed-out use | The app works without signing in. Data lives in SwiftData on the phone; Apple sign-in later uploads it to D1 and turns on sync |
| Scene | Sky and water fill the whole screen, drawn in SwiftUI from the `ref-img/` mockups. No photos |
| Location | 5-digit US zip typed in Settings. No location permission. Open-Meteo's geocoder returns place and timezone (checked) |
| Weather, sun, moon | Open-Meteo, called from the Worker. Moonrise, moonset and moon phase are returned (checked) |
| Calendars (changed) | No EventKit. The user pastes calendar links in Settings: Google's secret iCal address, an Apple published calendar link, an Outlook published link. The Worker fetches and parses them |
| Followed sites | The user enters a page URL and their own category name. The Worker uses the page's RSS/Atom feed if it advertises one, otherwise reads article links from the HTML |
| Today feed | Only the newest headlines that fit (about 3 to 5), published since yesterday. No scrolling |
| `>>` button | Opens a 7-day history of everything that appeared in the feed, with keyword search and category filter, and a save action per item |
| Asterisk button | Opens Saved (`ref-img/00-save-list.png`): search, category filter, notes, remove |
| Reading view | Title, source, date, the site's own excerpt, and "Read on original site". No full-text extraction |
| AI search | Settings holds an LLM API key, comma-separated interests, a max-searches-per-day cap, and the pill toggle "Use My List / Let AI Search". Providers: Anthropic, OpenAI, Google Gemini, Perplexity. AI-found items are blended into the feed and visibly labelled |
| LLM key | Stored only in the iPhone Keychain; sent with each search request to the Worker, which calls the provider and never stores or logs it |
| Do/Get | One screen, two sections, each with its own add field (`ref-img/00-do-get-list.png`) |
| `ref-img/` | Committed in full, including the 95 MB PDF |
| Out of v1 | Voice input, Siri/Shortcuts, widget, notifications, AI summarization |

Assumptions to confirm by screenshot, not blocking:
- Do/Get order: DO on top, GET below, as stated in the message (the mockup shows GET on top).
- `weather-detail.png`, `palette.png` and the `lake-michigan-*` photos are mood and colour references; there is no weather detail screen in v1.
- Rain and snow have no mockup; they are drawn as simple falling marks in the same flat style.

## Needs your approval (ask-first items)

New dependencies outside STACK:
- `ical.js` (API): parses `.ics` and expands repeating events.
- `fast-xml-parser` (API): parses RSS/Atom. The HTML fallback uses the Workers built-in `HTMLRewriter`, no package.
- Two open-licence fonts bundled in the app: Jost for the all-caps text, and a condensed bold face for the day name (candidate: Fira Sans Extra Condensed). Final match confirmed by Simulator screenshot.

## Design

### Root identity file
`app-identity.xcconfig` at the root (the hooks block `.env*` and `*.toml`):
```
APP_BUNDLE_ID = com.example.seasign
DEVELOPMENT_TEAM =
```
- `ios/project.yml` loads it through `configFiles` and sets `PRODUCT_BUNDLE_IDENTIFIER: $(APP_BUNDLE_ID)`.
- `api/wrangler.jsonc` carries the same bundle ID in `vars.APPLE_APP_BUNDLE_ID` for Better Auth's `appBundleIdentifier`. A small script, `api/scripts/check-identity.mjs` (run by `npm test`), fails if the two differ.

### API (`api/`, Hono + zod-openapi, all v1 routes need no account)

| route | does |
|---|---|
| `GET /v1/health` | scaffold check |
| `GET /v1/sky?zip=NNNNN` | geocodes the zip (KV, long cache), fetches Open-Meteo (KV, 15 min). Returns place, timezone, temperature, weather code, cloud cover, wind, gusts, sunrise, sunset, moonrise, moonset, moon phase |
| `POST /v1/calendar/events` | body: list of calendar links. Fetches each `.ics`, expands repeats, returns upcoming events soonest first |
| `POST /v1/sites/resolve` | body: page URL. Returns the discovered feed URL or "page links" mode, plus the site title |
| `POST /v1/feed` | body: list of sites. Returns items (title, link, source, published date, excerpt) from the last 7 days; per-site KV cache |
| `POST /v1/discover` | header `X-LLM-Key`; body: provider, interests. One adapter per provider using its web search; returns items with source links, marked `origin: "ai"` |

Rules for these open endpoints:
- https only (`webcal://` is rewritten to `https://`); reject private and local addresses; cap response size and time.
- Rate-limit per client IP.
- Never log or store LLM keys or calendar links. KV cache keys for calendars are a hash of the link, since a secret iCal link is a credential.
- Model IDs and web-search request shapes are looked up in each provider's current docs at implementation time, not from memory.

The Cron morning refresh waits for the sync milestone, because until users sign in the server does not know which sites they follow. In v1 the feed refreshes when the app opens.

### iOS (`ios/`, SwiftUI + SwiftData)

- **Design system**: colours from `ref-img/palette.png` and the mockups (sun `#FC6860`, day water `#B5DCE6`, sea `#4E8DB5`, night `#0C0D12`, charcoal sky from the mockups), the two fonts, letter-spaced caps text style.
- **SwiftData models**: `Settings` (zip, AI mode, interests, daily cap, provider), `CalendarLink`, `Site` (url, category, feed mode), `FeedItem` (pruned after 7 days), `SavedItem` (with notes), `ListItem` (kind do/get, done), `SearchCount` (per day, enforces the cap on the device).
- **Today**: date, day name, temperature, next three events; scene; headlines in the water; three icon buttons (settings, do/get, saved) and `>>`.
- **Scene** (`Canvas` + `TimelineView`): sun and moon placed along an arc from rise to set using the times for the user's zip and timezone; large sun at the horizon for sunrise and sunset; moon phase shape; stars at night; clouds from cloud cover; dashes on the water and a streaked reflection when windy; rain and snow from the weather code. A debug-only control forces any time and weather so every state can be screenshotted.
- **Settings**: zip; calendar links (add, remove); sites with category; AI section (provider, key into Keychain, interests, cap, pill toggle).
- **History** (`>>`), **Saved**, **Reading view**, **Do/Get** as in the mockups.
- AI items carry a visible "AI" label in the feed and history.

### Last milestone, blocked on the Apple Developer account
Better Auth with Sign in with Apple, D1 tables for lists, sites, saved items and settings (every query scoped by session user ID), sync routes, upload of local data on first sign-in, `DELETE /v1/account`, and the Cron morning refresh.

## Verification

- **API tasks**: `npm test` and `npx tsc --noEmit` in `api/`; route tests use recorded Open-Meteo, `.ics`, RSS and HTML fixtures and mocked LLM responses; `npx wrangler dev` answers each route; `npm run openapi` regenerates the spec and the iOS app still builds.
- **iOS tasks**: build and `test` with XcodeBuildMCP on the iOS 18.3 and iOS 27.2 Simulators; run against local `wrangler dev`; take a screenshot of each changed screen and compare it with the matching file in `ref-img/`.
- **Scene**: use the debug control to screenshot sunrise, midday, sunset, each moon phase, windy day and night, cloudy day and night, and compare with `01`–`11` in `ref-img/`.
- **Safety checks**: tests prove non-https and private-address URLs are rejected, and that LLM keys and calendar links never appear in logs or KV keys.
- **AI search with a real key** needs you to enter your own key in the Simulator; automated tests use mocks only.
