## Goal

User decision 2026-11-21: pasted iCal links are the slow fallback (Connect Google is the fast path), and a conditional 'has it changed?' check was considered and dropped as not worth its cost. The app asks for pasted-link events every 5 minutes instead of every 60 seconds, and the API caches a link's events for 5 minutes instead of 1. Fewer Worker requests and about a fifth of the KV writes.

## Acceptance criteria

- [x] iOS: EventsModel.refreshInterval is 5 minutes; the Today minute loop still runs (sky shares it) but sends a calendar request only when the last answer is 5 minutes old; the pull above the horizon, return to the foreground and adding or removing a link still fetch at once; Google events polling is untouched
- [x] API: CALENDAR_TTL in api/src/routes/calendar.ts is 300 seconds; comments and any test that states the 60-second value updated; a forced refresh from the app (pull) must still get fresh events: check how force reaches the API today and keep that behaviour, or say in the log if a pull can now return a cached answer up to 5 minutes old
- [x] memory/decisions/2026-11-19-google-calendar-api-and-refresh.md gets a dated line recording the new numbers and why; npm test and tsc pass; openapi unchanged; iOS suite passes on both runtimes
