## Goal

Plan plans/2026-11-19-google-calendar-push.md, task E. The app registers for remote notifications, gives the Worker its APNs device token with the chosen Google calendars (POST /v1/google/watch), reloads Google events when a background push arrives, and keeps the channels alive. Signing changes here (Push Notifications capability, aps-environment entitlement, Background Modes: remote notifications) were approved by the user in the plan on 2026-11-19. Look the Apple APIs up in sosumi first.

## Acceptance criteria

- [x] project.yml: Push Notifications entitlement (aps-environment) and UIBackgroundModes remote-notification, through XcodeGen only; xcodegen generate; the app builds for the Simulator on both runtimes. No user-visible notification permission is asked for (background pushes need none)
- [x] Registration: the app calls registerForRemoteNotifications at launch when Google is connected; on a device token it calls postGoogleWatch with the calendars that are on, the hex token and the environment (sandbox for Debug, production for Release); it re-registers when the chosen calendars change, when the device token changes, and when the app opens with a channel under 2 days from expiry; per-calendar errors and our 429 show a short status in Settings and never block polling
- [x] Disconnect and sign-in expiry call postGoogleUnwatch (best effort) before the token is dropped; the device token is kept only in memory or the user store, never logged
- [x] A background push with type calendar-changed triggers one Google events refresh and calls the completion handler with newData / noData / failed within the system's time limit; pushes arriving close together are coalesced into one fetch; the app still fetches on return to the foreground
- [x] Polling stays as the fallback: the 5-second poll continues while no channel is registered (Simulator without the deployed API, registration failed); when a channel is live the poll slows to once a minute (constant in one place)
- [x] Tests (Swift Testing, mocked transport): registration body, re-registration triggers, expiry rule, unwatch on disconnect, push handling and coalescing, poll rate with and without a channel. Suite passes on iPhone 16 / iOS 18.3.1 and iPhone 17 / iOS 27.2. Do not drive, screenshot or log the Pro Max simulator's Google account data
