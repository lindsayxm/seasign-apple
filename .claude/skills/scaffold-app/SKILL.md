# Scaffold the app

Run this under a claimed task. Stop and ask the user before anything on the "Ask the user first" list in AGENTS.md (creating cloud resources, signing, new dependencies outside STACK). Check `cloudflare-docs`, `better-auth` and `sosumi` for current APIs before writing framework code; do not rely on memory for versions or config shapes.

Ask the user for two values first: the **bundle identifier** (for example `com.example.seasign`) and the **Apple Developer team ID** (may be left empty for Simulator-only work).

## 1. `api/` — Cloudflare Worker

1. `npm create cloudflare@latest api` with the Hono template, TypeScript, no deploy, no git. Config goes in `api/wrangler.jsonc` (never `.toml`).
2. Install the STACK packages: `hono`, `@hono/zod-openapi`, `zod`, `drizzle-orm`, `better-auth`; dev: `drizzle-kit`, `vitest`, `@cloudflare/vitest-pool-workers`, `typescript`.
3. Layout:
   ```
   api/src/index.ts          OpenAPIHono app, mounts routes and /api/auth/*
   api/src/routes/           one file per resource, each route defined with createRoute + Zod schemas
   api/src/db/schema.ts      Drizzle schema (includes the Better Auth tables)
   api/src/auth.ts           createAuth(env): Better Auth per request, Drizzle adapter, bearer plugin, Apple provider
   api/migrations/           generated by drizzle-kit
   api/test/                 Vitest, workers pool
   ```
4. Declare the D1 and KV bindings in `wrangler.jsonc` with placeholder IDs for local use. Creating the real resources needs the user's go-ahead.
5. First route: `GET /v1/health`. First test: it returns 200.
6. `npm run openapi` script that writes `../openapi/openapi.json` from the app's `getOpenAPIDocument`.
7. Add `api/.env.example` with placeholder names only.

Verify: `npm test`, `npx tsc --noEmit`, `npx wrangler dev` answers `/v1/health`.

## 2. `openapi/` — contract

- `openapi/openapi.json` is generated by `npm run openapi` in `api/`. Never edit it by hand.
- `openapi/openapi-generator-config.yaml` for `swift-openapi-generator` (`generate: [types, client]`, `accessModifier: internal`).

## 3. `ios/` — SwiftUI app

1. `ios/project.yml` for XcodeGen:
   - app target `Seasign`, iOS 18.0, Swift 6, bundle ID and team from the user;
   - unit-test target `SeasignTests` (Swift Testing);
   - packages `swift-openapi-generator` (build plugin), `swift-openapi-runtime`, `swift-openapi-urlsession`;
   - the spec and generator config from `openapi/` referenced into the target so the client regenerates on build;
   - Info.plist usage strings for calendar and speech only when those features land, not now.
2. Layout:
   ```
   ios/Seasign/SeasignApp.swift     @main, model container
   ios/Seasign/Today/               Today screen
   ios/Seasign/API/                 thin wrapper over the generated client (base URL, bearer token)
   ios/Seasign/Auth/                Sign in with Apple, Keychain session store
   ios/SeasignTests/
   ```
3. `cd ios && xcodegen generate`. The `.xcodeproj` is git-ignored and never hand-edited.

Verify with XcodeBuildMCP: build for the iPhone 16 simulator, run the tests, launch the app, take a screenshot. Equivalent CLI: `xcodebuild -project ios/Seasign.xcodeproj -scheme Seasign -destination 'platform=iOS Simulator,name=iPhone 16' test`.
